# SH2SC-EDT — Документація Українською {#ukrainian_mainpage}

## Ідентифікація проєкту

**SH2SC-EDT** — *Самовідновлюваний апаратно-програмний комплекс для зашифрованої передачі даних*
(Self-Healing Hardware and Software Complex for Encrypted Data Transmission).

**C2P-ARQ** — *Автоматичний запит повторної передачі ChaCha-Poly*
(ChaCha-Poly Automatic Repeat reQuest). Спеціалізований протокол сесійного рівня, що керує
всім обміном між вузлом A (Передавач) та вузлом B (Приймач).

---

## Огляд системи

SH2SC-EDT — це відмовостійкий, криптографічно захищений комплекс передачі даних, реалізований
на двох мікроконтролерах Arduino Nano (ATmega328P, 8-біт AVR, 16 МГц, 2 КБ SRAM).
Система демонструє, що автентифікована зашифрована передача даних можлива над каналом
з апаратними перешкодами, використовуючи лише 256-бітний завчасно розподілений симетричний
ключ і 8-бітний мікроконтролер.

Середовище симуляції: **SimulIDE** (симулятор реального часу). Вся прошивка є суворо
неблокуючою: відсутні виклики `delay()` у тілі циклу, усі тайм-аути реалізовано через
дельти `millis()`.

Академічний контекст: курсова робота з дисципліни *«Архітектура комп'ютерних систем»*.

---

## Протокол C2P-ARQ

Протокол C2P-ARQ реалізує три фази на кожну сесію передачі:

**Фаза 1 — Відкриття сесії (SYN-рукостискання)**

> TX генерує 12-байтний одноразовий вектор (nonce) через ГПВП і надсилає його у пакеті
> `HelloPacket` (FLAG\_SYN). RX зберігає nonce, встановлює `MASTER_PSK` і відповідає `ACK_BYTE`.

**Фаза 2 — Передача даних (ARQ «Зупинись і чекай»)**

> Для кожної ноти: TX виводить унікальний вектор ініціалізації (IV) для пакету, шифрує
> 4-байтне корисне навантаження алгоритмом ChaCha20, додає скорочений 8-байтний MAC Poly1305
> та надсилає кадр із преамбулою `0xAA 0x55`. RX верифікує MAC перед будь-якими діями
> над корисним навантаженням.
> На `ACK`: перейти до наступного індексу. На `NACK` або тайм-аут: повторна передача
> (до `MAX_RETRIES = 50` спроб).

**Фаза 3 — Завершення сесії (FIN teardown)**

> TX надсилає кадр `FLAG_FIN` (автентифікований, нульове корисне навантаження). Обидва вузли
> стирають `s_sessionNonce` з оперативної пам'яті через `memset()` після автентифікованого
> завершення.

### Виведення вектора ініціалізації для пакету

Ніякий IV не передається по каналу. IV кожного пакету визначається локально:

```
packetNonce[0..11] = s_sessionNonce[0..11]   // локальна копія — оригінал не змінюється
packetNonce[10]   ^= (seqNum >> 8) & 0xFF
packetNonce[11]   ^= (seqNum)      & 0xFF
```

Усі 65 536 можливих значень `seqNum` породжують унікальні IV без жодної додаткової передачі.

### Формати кадрів

| Кадр | Розмір (дроті) | Структура |
|------|----------------|-----------|
| `HelloPacket` | 15 байт | `0xAA 0x55` + `flags(1)` + `nonce(12)` |
| `DataPacket`  | 17 байт | `0xAA 0x55` + `flags(1)` + `seq_num(2)` + `ciphertext(4)` + `mac(8)` |

3-байтні AAD `{flags, seq_lo, seq_hi}` автентифікуються, але не шифруються;
будь-яка зміна байту прапора чи порядкового номера призводить до відмови MAC.

## Архітектура — «Жирний сервер / Тонкий клієнт»

Система побудована навколо навмисної асиметрії:

| Властивість | Вузол A — Передавач («Диригент») | Вузол B — Приймач («Синтезатор») |
|-------------|----------------------------------|-----------------------------------|
| **Стан** | Зберігає `melodyIndex`, керує повним циклом сесії | Без стану між пакетами; зберігає лише `s_sessionNonce` |
| **Дані** | Повна мелодія у `PROGMEM` (530 нот) | Універсальний словник із 21 частот |
| **КА** | 9 станів: `IDLE` → `WAITING_FIN_ACK` + `RECONNECTING` | Аналізатор байтів: `WAIT_AA → WAIT_55 → READ_TYPE → READ_PAYLOAD` |
| **Крипто** | Шифрує, генерує nonce, надсилає MAC | Дешифрує, верифікує MAC, відхиляє при невідповідності |

Розподіл досягає двох цілей: ефективне використання пам'яті (дорогі обчислення — на TX)
та розширюваність (заміна індексів нот на командні ID не вимагає змін прошивки RX).

## Самовідновлення — Автоматичне відновлення передачі

Визначальна властивість SH2SC-EDT — автоматичне відновлення сесії без втрати даних
і без втручання оператора.

**Послідовність відновлення після тривалої перерви зв'язку:**

1. TX повторно передає поточний пакет до `MAX_RETRIES = 50` разів
   (`ACK_TIMEOUT_MS = 50 мс` на спробу — загальне вікно `2,5 с`).
2. Викликається `suspendSession()`: `s_sessionNonce` обнуляється, `retryCount` скидається.
   **`melodyIndex` навмисно зберігається** — це контрольна точка самовідновлення.
3. TX переходить у стан `TxState::RECONNECTING` і транслює новий `HelloPacket` щорзу
   `RECONNECT_INTERVAL_MS = 2000 мс`.
4. Після відновлення каналу RX отримує `HelloPacket`, зберігає новий nonce, надсилає `ACK`.
5. TX читає збережений `melodyIndex` і **відновлює передачу з точної ноти збою** —
   не з початку.

Без самовідновлення перешкода тривалістю понад `2,5 с` назавжди зупиняє передачу.
З ним комплекс повністю автономний.

## Динамічний розумний сторожовий таймер (Приймач)

Приймач не може виявити відключення TX без отримання пакету `FLAG_FIN`. Статичний тайм-аут
спрацьовував би зарано на довгих нотах або занадто пізно на коротких.

**Рішення:** після кожного автентифікованого `DataPacket` RX оновлює:

```
current_timeout_limit = durationMs + NETWORK_GRACE_PERIOD_MS  // 3000 мс
last_valid_packet_time = millis()
```

`NETWORK_GRACE_PERIOD_MS = 3000 мс` поглинає найгіршу бурю повторних передач TX
(`50 × 50 мс = 2500 мс`). При тайм-ауті: `s_sessionNonce` обнуляється, сесія звільняється,
аналізатор скидається у `WAIT_AA` — готовий до нового рукостискання без перезапуску МК.

## Криптографічні властивості безпеки

- `MASTER_PSK[32]` (256-біт) скомпільований у прошивку; ніколи не передається і не
  виводиться в журнал.
- Сесійний 96-бітний nonce від ГПВП; початкова ентропія 256 біт (кільцевий осцилятор,
  неініціалізована SRAM, АЦП температури, TCNT1, шум A0, `random()`).
- Скорочений 8-байтний MAC Poly1305 на кожному кадрі (повний тег обчислюється, перші
  8 байт передаються).
- Сесійний nonce стирається через `memset(s_sessionNonce, 0, 12)` при кожному закритті
  або збої.
- Перевірка меж `noteIndex < NOTE_DICT_SIZE` перед будь-яким зверненням до масиву —
  запобігає читанню поза межами на ATmega328P з пошкоджених корисних навантажень.
- Без `String`, `new` або `malloc()` — усі буфери статично виділені під час компіляції.
